# Code Style Guidelines for Shopping List Project

## Core Principles

- **Plain JavaScript only** - No frameworks, no libraries, no external dependencies
- **Keep it simple** - Straightforward, readable code over clever tricks
- **Global scope is fine** - When sharing makes sense, use the global scope
- **Avoid heavy OOP** - Prefer functions over classes; simple objects over inheritance
- **No IIFEs** - No wrapping code in `(function(){...})()` patterns
- **"use strict"** - Always include at the top of each file

## Code Organization

- Group related functionality with comment headers: `// ================= Section Name =================`
- Use descriptive function names: `saveCurrentList()`, `renderSection()`, `scheduleSave()`
- Keep functions focused and reasonably sized
- Declare module-level variables at the top (using `let` or `const`)
- Modules may well keep their functions in the global namespace.
- Do not pass many callbacks back and forth between modules unless necessary

## JavaScript Style

- Use `let` and `const` (not `var`)
- Arrow functions for callbacks: `items.forEach(item => ...)`
- Regular functions for top-level definitions: `function render() { ... }`
- Template literals when constructing strings with variables
- Optional chaining when appropriate: `currentList?.bgColor`
- Not too many callbacks. 

## DOM Manipulation

- Direct DOM API - `document.createElement()`, `appendChild()`, etc.
- Set styles directly: `element.style.backgroundColor = color`
- Event handlers as properties: `button.onclick = () => { ... }`
- Use `contentEditable` for inline editing

## Naming Conventions

- camelCase for variables and functions: `currentList`, `renderItem()`
- Descriptive names over abbreviations (except common ones like `btn`, `idx`)
- Prefix with verbs for functions: `get`, `set`, `create`, `render`, `schedule`

## Comments

- Use comments for major sections and non-obvious logic
- Avoid stating the obvious
- Explain *why* when the reason isn't clear

## What to Avoid

- Framework dependencies (React, Vue, jQuery, etc.)
- Build tools or transpilation requirements
- Complex class hierarchies
- Module bundlers (code should run directly in browser)
- IIFE wrappers: `(function(){ ... })()`
- Over-abstraction

## Project-Specific Patterns

- Modules should use global namespace pattern, with one object like window.util that lists public functions
- Use `scheduleSave()` pattern for debounced saves
- Keep data and UI in sync through re-rendering
- Store references in DOM nodes using underscore prefix: `element._item = item`
